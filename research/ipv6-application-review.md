## Interpretation and baseline

This inventory covers all 12 application services in base Compose and all five additional applications in `compose.full.yaml` and `compose.agent.yaml`. It distinguishes a configuration fact from an operational failure. An IPv4 listener on a network with both address families is not automatically a defect: a working IPv4 route may satisfy the application flow. Conversely, a working IPv4 probe does not establish IPv6 reachability.

The branch adds `enable_ipv6: ${IPV6_ENABLED}` to the base network; the pre-fix base Compose file did not set this property. Thus enabling network IPv6 is a branch behavior change, not merely documenting an already-wired base Compose option. The four application flag consumers below already existed before that change. The branch also removes the explicit Locust IPv4 bind override and renames Envoy's destination variable to `LOAD_GENERATOR_WEB_HOST`. No other application implementation in this table changes between the two commits.

Across the inspected application code, no explicit `tcp4`/`tcp6`, `AF_INET`, `ipv6Only`, `IPV6_V6ONLY`, Node DNS order override, or Kafka address-family preference was found. This is scoped evidence from source/configuration inspection, not proof about transitive dependency defaults. Exporters and flag clients generally receive service hostnames from Compose; the flag does not globally rewrite clients or their resolution behavior.

## Documentation implications

- Describe lowercase `true` / `false` explicitly. All four source consumers compare the value to the exact lowercase string `true`; do not promise alternative spellings without checking Compose and application parsing together.
- Explain the separate effects: bridge address assignment (new base-Compose wiring in this branch), four application bind choices (pre-existing), and hostname resolution by clients (not universally controlled by the flag).
- Neither `false` nor `true` is a global forced-address-family policy. Services without a flag consumer use their own framework/configuration defaults.
- Localhost health checks are startup/liveness checks, not evidence of cross-container reachability in both families. Payment/shipping explicitly probe IPv4.
- Do not describe IPv6-only support as established. The agreed proposed objective is normal operation on dual-stack networking; mandatory direct IPv6 access to every endpoint is a separate acceptance decision.
