No containers were started. References below are repository paths and line numbers at this checkout.

## Interpretation

The local branch introduces `enable_ipv6: ${IPV6_ENABLED}` at `compose.yaml:25` and `compose.profiling.yaml:8`; this is a branch change, not the pre-fix baseline. No infrastructure service receives `IPV6_ENABLED` as a process environment variable. Their listener choices therefore remain independent of the network flag.

The pinned Envoy image is v1.39.3 (`src/frontend-proxy/Dockerfile:4`). Every cluster in `src/frontend-proxy/envoy.tmpl.yaml:165` onward uses `STRICT_DNS`, without `dns_lookup_family`. The [version-matched Envoy reference](https://www.envoyproxy.io/docs/envoy/v1.39.3/api-v3/config/cluster/v3/cluster.proto#enum-config-cluster-v3-cluster-dnslookupfamily) identifies `AUTO` as the default, preferring IPv6 DNS results. Its fallback is a DNS-family lookup fallback; it must not be represented as guaranteed fallback after an IPv6 connection fails. `ALL` returns both families with Happy Eyeballs, but choosing it is a separate design decision.

A wildcard literal alone is insufficient to diagnose a bug across runtimes. [Go net.Listen](https://pkg.go.dev/net#Listen) documents that unspecified addresses with `tcp` can listen on all available addresses, whereas a hostname creates a listener for at most one resolved IP. Consequently Go-based `0.0.0.0` settings must not automatically be classified as IPv4-only. Hostname-based *listeners* warrant attention as well as wildcard searches.

## Follow-up priorities

1. Keep the existing Locust issue focused. The branch already changes its override and destination variable; do not call it an unresolved upstream regression without separating baselines.
2. Review collector hostname-based receiver binding first: it participates in almost every service's telemetry path and is also selected directly by Envoy.
3. Treat direct IPv6 ingress to Envoy separately from Envoy's upstream IPv6 selection. Host port forwarding can obscure the container's actual listener family.
4. Inspect pinned external source/image defaults before proposing service issues for flagd, databases, OpAMP and firepit. These inventory entries are intentionally unresolved, not assumed defects.
5. Targeted runtime follow-up can use one backend plus a probe container on a temporary dual-stack network. Record DNS A/AAAA results, actual sockets, and forced-family requests. No full-stack load generation is required to settle individual socket questions.
